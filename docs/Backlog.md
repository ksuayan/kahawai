# Backlog

Things we decided to leave for later, with enough context to pick them up cold. Newest thinking wins: edit freely. Size is a rough guess: **S** = an hour or two, **M** = a day, **L** = several days.

**Status** — `Not started` · `Partial` (some of it landed) · `Needs verification` (code looks done, not confirmed) · `Won't do` (deliberately out of scope) · `Done` (kept here only until its follow-ups are cleared).
**Phase** — `v1 polish` (rounds out what's shipped) · `v2` (new capability, tracked spec or not) · `Research` (needs a spike before it's schedulable) · `Housekeeping` (repo/process, not product).
**Priority** — `P1` (do next) · `P2` (worth doing, not urgent) · `P3` (nice to have / conditional on something else happening first).

## Headphone correction: AutoEq import

Goal: let a user load a headphone correction profile (the AutoEq `ParametricEQ.txt` format, `Preamp: -6.2 dB` then `Filter N: ON PK|LSC|HSC Fc … Hz Gain … dB Q …` lines) into the EQ. **Import only: Kahawai ships no profile data.** AutoEq's code is MIT, but its README states no licence or permission terms for the measurements (oratory1990, Crinacle, Innerfidelity, Rtings) the profiles are computed from, so bundling profiles is a separate, unresolved question (last story). The stories below are ordered by dependency. Gap analysis: the EQ already has every filter type AutoEq uses; what is missing is the band count, a preamp, a shelf-Q conversion and the import itself. Confirm the file format against a real AutoEq download before building the parser (this list is from memory).

| Item | Why / notes | Details | Status |
|---|---|---|---|
| **Raise the 8-band EQ cap** | *As a user with an AutoEq profile, I want all of its filters to load.* Typical profiles have 10 filters, more than `MAX_EQ_BANDS = 8` ([dsp.rs](../crates/kahawai-player-core/src/dsp.rs)), so they would not fit. Raise the cap (10 to 12), then check that the UI in [EqEditor.vue](../player/ui/src/components/EqEditor.vue) still lays out and that DSP cost is acceptable (biquads are cheap, so this is mostly a UI and test task). Prerequisite for the import. | Size: **S**<br>Phase: **v2**<br>Priority: **P2** | **Not started** |

The EQ has no pre-gain (see "Reuse the level meter for the EQ" below); the look-ahead limiter would duck the peaks, which is not the same as attenuating first. Add an EQ preamp (dB) applied before the filters or through the existing loudness gain ramp, persisted with the bands and part of a preset, with the same click-free ramp as live edits. Also lets a hand-made EQ use it. | Size: **M**<br>Phase: **v2**<br>Priority: **P2** | **Not started** |

## Playback and streaming

| Item | Why / notes | Details | Status |
|---|---|---|---|
| **Clicks on pause, resume, seek, skip and volume changes** | Some transitions are smoothed already: the loudness gain ramp between tracks (~50 ms), EQ edits, and the analog-warmth and crossfeed on/off fades. The transport isn't: `pause()`, `resume()`, `stop()`, `seek_ms()` and `next()`/`prev()` ([engine.rs](../crates/kahawai-player-core/src/engine.rs)) cut or start the stream instantly, mid-waveform, which clicks, loudest on bass-heavy material. ## DSP effects (research first)

Both items below need the same groundwork, so plan them together:

- **A stage seam.** Extract the `DspStage` trait sketched in v1/EQ.md section 6, so the EQ, tape and tube stages are interchangeable and orderable in the PCM chain (decode, resample, [stages], loudness, volume).
- **Oversampling.** Saturation creates harmonics above the original bandwidth; without 2x to 8x oversampling around the non-linear part they alias back as harsh, inharmonic distortion. This is the main CPU cost, and the playback thread must still keep ahead of the device (see the 200 ms ring buffer in [cpal_sink.rs](../crates/kahawai-player-audio/src/cpal_sink.rs)).
- **Same path rules as the EQ.** PCM shared path only. DoP and bit-perfect playback bypass these effects, and the UI dims them with the same "not supported for this stream type" message.
- **Level discipline.** Non-linear stages care about input level. Decide where in the chain they sit relative to loudness normalization and volume (level in, level out, and a drive control), and add a gain-matched A/B so "better" is not just "louder".
- **Live edits without clicks.** Reuse the EQ's fade approach for parameter changes and on/off.
- **Licensing and naming.** Prefer our own implementations from published papers and measurements. Check the licence before borrowing from open-source emulations (some are GPL). Use "inspired by" wording for classic gear names; the names are other companies' trademarks.

| Item | Why / notes | Details | Status |
|---|---|---|---|
| **Pop and click reduction (declicker) for vinyl rips** | Dust and scratches on digitized vinyl come through as clicks (isolated impulses a fraction of a millisecond long), crackle (dense small ticks) and the occasional larger pop. A playback-time declicker would clean them up without touching the files (the scanner is read-only by design, so no offline repair). **Approach, from the restoration literature:** detect impulses as outliers in a linear-prediction (AR model) residual, or in a high-passed signal, against a running threshold; then replace just the corrupted samples by interpolating from the samples around them (least-squares AR interpolation, not a plain low-pass, so the music under the click is kept). Crackle may need a lower threshold and a shorter maximum length; big pops (low-frequency thumps from deep scratches) are a separate, harder problem and can be left out of a first version. **Controls:** on/off, sensitivity, and maybe a maximum click length (~0.1–5 ms); off by default. **Engine:** a new `DspStage` on the PCM shared path, like crossfeed: a bit-perfect blocker while on, first in the chain (before crossfeed and EQ); it needs a short look-ahead window, so report it as `latency_frames` (the look-ahead limiter shows the pattern). Per channel, with detection optionally linked across both (a click often hits both channels at once). **Risks:** false positives on sharp transients (harpsichord, rimshots, plucked strings) dull the attack, so tune on real music, not just synthetic clicks; CPU is modest at 44.1/96 kHz but should be measured at 192 kHz. **Tests:** synthetic clicks added to sine and music excerpts, checking detection rate, what's left afterwards, and that clean audio passes through untouched.
