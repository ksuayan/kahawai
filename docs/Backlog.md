# Backlog

Things we decided to leave for later, with enough context to pick them up cold. Newest thinking wins: edit freely. Size is a rough guess: **S** = an hour or two, **M** = a day, **L** = several days.

**Status** — `Not started` · `Partial` (some of it landed) · `Needs verification` (code looks done, not confirmed) · `Won't do` (deliberately out of scope) · `Done` (kept here only until its follow-ups are cleared).
**Phase** — `v1 polish` (rounds out what's shipped) · `v2` (new capability, tracked spec or not) · `Research` (needs a spike before it's schedulable) · `Housekeeping` (repo/process, not product).
**Priority** — `P1` (do next) · `P2` (worth doing, not urgent) · `P3` (nice to have / conditional on something else happening first).

## Headphone correction: AutoEq import

Goal: let a user load a headphone correction profile (the AutoEq `ParametricEQ.txt` format, `Preamp: -6.2 dB` then `Filter N: ON PK|LSC|HSC Fc … Hz Gain … dB Q …` lines) into the EQ. **Import only: Kahawai ships no profile data.** AutoEq's code is MIT, but its README states no licence or permission terms for the measurements (oratory1990, Crinacle, Innerfidelity, Rtings) the profiles are computed from, so bundling profiles is a separate, unresolved question (last story). The stories below are ordered by dependency. Gap analysis: the EQ already has every filter type AutoEq uses; what is missing is the band count, a preamp, a shelf-Q conversion and the import itself. Confirm the file format against a real AutoEq download before building the parser (this list is from memory).

|---|---|---|---|

## UPnP / DLNA media server

*As someone with a TV, an AV receiver, a network streamer or a phone app on the home network, I want Kahawai to show up as a music library I can browse by album, artist, genre and playlist and play from, with no Kahawai app on that device.* This is what the VLC spec parked ([kahawai-server-vlc-client-spec.md](v1/kahawai-server-vlc-client-spec.md), "Parked"): a UPnP AV **MediaServer** that VLC's **Local Network → Universal Plug'n'Play**, TVs, receivers and control-point apps discover on their own. It makes the server discoverable and browsable from every device on the LAN without a login, which is why it should be **opt-in** (off by default, a switch in the Server app), in keeping with the trusted-LAN rule.

**How large:** roughly **two weeks of work, in two halves.** About a week (SSDP, descriptions, Browse, DIDL-Lite, the setting) gives a server that VLC and phone control-point apps can browse and play. The second week is device compatibility: DLNA headers and profiles, eventing, Search, and testing on real TVs and receivers, each of which has quirks. On this backlog's scale that's two **L**s, or about 9 to 12 days across the stories below. Start with the spike, because whether a Rust crate can carry the protocol plumbing moves the estimate by a few days either way.

**What carries over from `vlc-server`:** the VLC-safe rendition table (`export::vlc_rendition`: passthrough where the device can decode, FLAC for DSD, SACD ISO and missing files left out), absolute URLs built from the address the client used, `Content-Disposition`, artwork URLs, and the transcode cache. The cache matters most: DLNA devices seek with byte ranges, which a cached render supports and a live transcode doesn't.

**Caveats:** VLC's UPnP browsing is slow on big trees (the reason this was parked), so a TV, receiver or phone app is the real target, not VLC. Every device decides for itself which formats it plays; many TVs take no FLAC above 48 kHz, and some take no FLAC at all. The renditions may have to vary by client (`User-Agent`), and that table grows by testing. No SACD ISO, as everywhere.

## DSP effects (research first)

Both items below need the same groundwork, so plan them together:

- **A stage seam.** Extract the `DspStage` trait sketched in v1/EQ.md section 6, so the EQ, tape and tube stages are interchangeable and orderable in the PCM chain (decode, resample, [stages], loudness, volume).
- **Oversampling.** Saturation creates harmonics above the original bandwidth; without 2x to 8x oversampling around the non-linear part they alias back as harsh, inharmonic distortion. This is the main CPU cost, and the playback thread must still keep ahead of the device (see the 200 ms ring buffer in [cpal_sink.rs](../crates/kahawai-player-audio/src/cpal_sink.rs)).
- **Same path rules as the EQ.** PCM shared path only. DoP and bit-perfect playback bypass these effects, and the UI dims them with the same "not supported for this stream type" message.
- **Level discipline.** Non-linear stages care about input level. Decide where in the chain they sit relative to loudness normalization and volume (level in, level out, and a drive control), and add a gain-matched A/B so "better" is not just "louder".
- **Live edits without clicks.** Reuse the EQ's fade approach for parameter changes and on/off.
- **Licensing and naming.** Prefer our own implementations from published papers and measurements. Check the licence before borrowing from open-source emulations (some are GPL). Use "inspired by" wording for classic gear names; the names are other companies' trademarks.

| **Pop and click reduction (declicker) for vinyl rips** | Dust and scratches on digitized vinyl come through as clicks (isolated impulses a fraction of a millisecond long), crackle (dense small ticks) and the occasional larger pop. A playback-time declicker would clean them up without touching the files (the scanner is read-only by design, so no offline repair). **Approach, from the restoration literature:** detect impulses as outliers in a linear-prediction (AR model) residual, or in a high-passed signal, against a running threshold; then replace just the corrupted samples by interpolating from the samples around them (least-squares AR interpolation, not a plain low-pass, so the music under the click is kept). Crackle may need a lower threshold and a shorter maximum length; big pops (low-frequency thumps from deep scratches) are a separate, harder problem and can be left out of a first version. **Controls:** on/off, sensitivity, and maybe a maximum click length (~0.1–5 ms); off by default. **Engine:** a new `DspStage` on the PCM shared path, like crossfeed: a bit-perfect blocker while on, first in the chain (before crossfeed and EQ); it needs a short look-ahead window, so report it as `latency_frames` (the look-ahead limiter shows the pattern).
